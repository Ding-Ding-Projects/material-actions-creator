How it works

Six stages.
Nothing left behind.

Every build is isolated in its own private repository, so builds never share state, never touch your real projects, and never linger.

Repo

A private mac-tmp-* repository is created under your user or organization.

Commit

Your Dockerfile and extra files land in context/, next to a generated workflow.

Dispatch

The workflow is started with workflow_dispatch — no push triggers, no surprises.

Build

Buildx (plus QEMU for non-x86 targets) builds the image and saves it with docker save.

Download

The artifact streams to the server and is unpacked into a plain .tar.gz.

Delete

The repository is deleted whether the build passed or failed. A sweeper catches anything a crash left behind.

Encrypted public builder

Public runner.
Private bytes.

Pick Encrypted public builder and the build runs in a throwaway public repository that only ever holds ciphertext.

What happens

A fresh 32-byte key is made for every run. The source snapshot is sealed into src.mac (AES-256-GCM, chunked and authenticated) and committed with a copy of the mac-crypt tool. The key goes in as the MAC_KEY Actions secret, sealed to the repository's public key. On the runner the workflow opens the sources, runs your scripts, seals the outputs into out.mac and uploads only that. The app downloads it, decrypts it, lists each file for download, then deletes the repository and revokes the key.

Temporary key

Configure a GitHub App (GITHUB_APP_ID, GITHUB_APP_PRIVATE_KEY, GITHUB_APP_INSTALLATION_ID) and each encrypted run mints its own installation token: it expires after an hour and is revoked as soon as the run is cleaned up. Without an App, the signed-in session is used.

Still public

The repository name, the workflow file, the run logs, file sizes and timing. Build scripts that print paths or file contents print them in public logs. Secret values are masked.

Read GitHub's terms first

Public repositories get free Actions minutes. GitHub's Actions terms expect workflows to serve the project in that repository, and throwaway repositories holding only encrypted private code can look like avoiding billing. That can get an account flagged. The private temp repo mode has no such issue.

mac-crypt skill

Make any workflow
encryption-ready.

Every workflow the app generates already speaks mac-crypt. Add two steps to your own workflows and the app can feed them encrypted inputs and read their encrypted outputs — on Linux, macOS and Windows runners.

Two steps

- uses: Ding-Ding-Projects/material-actions-creator/.github/actions/mac-crypt@main with: mode: open key: ${{ secrets.MAC_KEY }} input: src.mac path: src # … your build … - uses: Ding-Ding-Projects/material-actions-creator/.github/actions/mac-crypt@main with: mode: seal key: ${{ secrets.MAC_KEY }} path: src globs: dist/**/*.exe, dist/**/*.msi output: out.mac

Or the CLI

One self-contained file, Node built-ins only.

node mac-crypt.mjs keygen node mac-crypt.mjs seal out.mac src "dist/**/*.exe" node mac-crypt.mjs open out.mac back

Chunks are bound to their position and to an end marker, so a reordered, truncated or extended file fails to open. Bundles refuse paths that would escape the destination.

Command line

Everything, from
a terminal.

The mac command does what the web app does — sign-in, scans, builds, Dockerfiles, runs, downloads — against a private in-process engine or a running server.

Build a repository

mac login mac scan Ding-Ding-Projects/map-editor mac build Ding-Ding-Projects/map-editor \ --all-scripts --all-workflows --encrypted \ --out ./outputs

Assisted sign-in

mac login runs the GitHub CLI device flow with repo, workflow and delete_repo, prints the one-time code and waits. mac login --refresh adds missing scopes.

Survives Ctrl+C

The build keeps running on GitHub; mac watch <id> picks it up from the journal.

Scriptable

id=$(mac build owner/repo --all-workflows --detach --json | jq -r .id) mac watch "$id" --out dist/ && mac rm "$id"

Your own workflows

Run the workflows
you already have.

Tick any workflow in the repository — or all of them. Each one runs inside the temporary repository, rewritten so it can't publish anything and, in encrypted mode, so nothing readable leaves the runner.

Triggers

Manual start only

  • Push, tag, schedule and PR triggers become workflow_dispatch
  • Reusable workflows keep workflow_call and are included so calls resolve
Safety

Read-only token

  • Permissions forced to read-only on the workflow and every job
  • Releases, Pages, package publishing and auto-commits removed; image pushes disabled
Encryption

Sealed artifacts

  • Sources decrypted right after checkout
  • Every uploaded artifact sealed, every downloaded one opened
  • All of them come back to you decrypted

If the app closes

Builds don't stop
when the app does.

Tab closed

Nothing happens

  • The server keeps running builds
  • Reopen the page and it catches up live
Server stopped

Journal resumes

  • Every stage is written to /data/journal.json
  • On start, each unfinished build is reattached to its run, its outputs are downloaded and decrypted, and the repository is deleted
  • GitHub keeps artifacts for a day, so there's a day to come back
Never came back

Sweeper

  • At startup, mac-tmp-* and mac-pub-* repositories older than three hours that aren't in the journal are deleted
  • Or click Sweep leftovers

Quick start

One container.
One sign-in.

Run it

The image bundles GitHub CLI. Mount a volume so the sign-in survives restarts.

docker build -t material-actions-creator . docker run -d --name mac -p 8080:8080 \ -v mac-data:/data \ -e GITHUB_OWNER=Ding-Ding-Projects \ material-actions-creator

Assisted sign-in

Click Sign in with GitHub CLI. The server runs gh auth login --web and shows the device code right in the app:

7F3K-Q9XD

Already signed in without the right scopes? Add missing scopes runs gh auth refresh.

Scopes requested

Exactly what the pipeline needs — nothing more.

repo · workflow · delete_repo · read:org

Use the image

Downloads stay available for an hour by default, then they're wiped from disk.

docker load -i node-app_latest.tar.gz docker run --rm node-app:latest

Prefer a token?

Set GITHUB_TOKEN to a classic personal access token with the same scopes and the CLI sign-in is skipped.

Lock it down

Set APP_ACCESS_KEY and the API asks for a key before anyone can build or download.
